# CLAUDE.md

Project context for Claude Code sessions — **not for humans**: never link or
reference this file from `README.md`, `CONTRIBUTING.md`, or anything under
`docs/`. A human contributor's path is `README.md` -> `docs/*.md` ->
`CONTRIBUTING.md`. Repo conventions (lanes, devcontainer, machine user,
credentials and secret tiers, mise, pre-commit, releases) follow
homelab-proxmox-core; its CLAUDE.md is the reference for anything this file
doesn't say. The SRE AI-autonomy roadmap is core's `docs/SRE-AI.md`; this
repo's `docs/SRE-AI.md` only points there.

## What this is

The homelab's Elastic observability platform, replacing
homelab-proxmox-workloads: Proxmox VMs for the Elastic Stack (Layer 1),
platform-wide Elastic configuration, Fleet agent policies per host group,
and workspaces (one Kibana space per thing observed) built by the
terraform-elasticstack-workspace module. It is also the learning reference
for the work platform on Elastic Cloud, which is built separately: nothing
there depends on this repo.

## Decisions that are deliberate (do not "fix" these)

- **Three scopes, narrowest wins:** shared (`shared/`), per host group
  (`agent-policies/<group>/`), per workspace (`workspaces/<id>/`).
  `docs/STACKS.md` has the table and the "what is a stack" rule.
- **One stack per workspace and per host group.** Never a `for_each` over
  all of them in one stack.
- **Folders hold data, not HCL.** Workspace and agent-policy stacks contain
  YAML and Kibana exports; Terramate generates their code
  (`terramate/workspace.tm.hcl`, `terramate/agent_policy.tm.hcl`). Never
  hand-edit a `_terramate_*.tf`; change the generator and run
  `terramate generate`.
- **Providers and backends are generated by tag** (`proxmox`,
  `elasticstack`), so a stack only ever gets one provider's credentials.
- **Namespace = workspace id** is the only contract with the module.
  `scripts/check_contract.py` enforces ids, `read_from`, agent-policy
  namespaces and package versions.
- **The workspace module ref is read at generate time** from
  `workspace.yaml`'s `module_ref`, falling back to the global
  `workspace_module_ref`: a module source must be a literal.
- **Agent policies are plain generated resources**, not a module: the YAML
  is the interface. Policy id = folder name.
- **VM stacks use core's VM module** by exact tag (global
  `core_vm_module`), never a copy.
- **Ansible is not a stack and never reads OpenTofu state** (divergence
  from core, whose inventory comes from `tofu output`): a Proxmox
  dynamic inventory groups VMs by tag. The enrollment token is looked up
  from the Fleet API by policy id, never output by a stack.
- **Git safeguards stay on for plan and apply** (`terramate run` refuses
  uncommitted or untracked files); only `mise run validate` disables them.
- **Stack selection is TM_SELECT**, an environment variable, because mise
  appends `--` arguments to the end of the command, which is `sops`.
- **HCP workspace per stack**, named `platform-<path>`, organization
  `homelab-bcochofel-com`, execution mode Local.

## Standing rules

- Never run `tofu plan/apply`, `terramate run` with credentials, or
  `ansible-playbook` against hosts: `mise run check` and `mise run
  validate` need none and are the agent's checks.
- A new workspace or host group passes `mise run contract` and
  `mise run tm:check` before the pull request.
- Resource schemas come from the Terraform MCP server or
  <https://search.opentofu.org>, never from memory.

## Commands

```bash
mise run check      # pre-commit, gitleaks, Terramate generated code, namespace contract
mise run validate   # tofu validate in every stack, no credentials
mise run tm:generate
```
