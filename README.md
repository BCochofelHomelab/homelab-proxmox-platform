# homelab-proxmox-platform

Everything behind the homelab's edge: an Elastic Stack and the
OpenTelemetry demo that sends it data, on Proxmox VMs. The edge itself (the
Caddy reverse proxy and the CoreDNS + Pi-hole DNS pair) is
[`homelab-proxmox-core`](https://github.com/BCochofelHomelab/homelab-proxmox-core),
whose conventions and guardrails this repository follows.

| VM | IP | Runs |
| --- | --- | --- |
| `es-01`, `es-02`, `es-03` | `192.168.68.30`–`.32` | Elasticsearch |
| `kibana` | `.33` | Kibana and Fleet Server |
| `ingest` | `.34` | Logstash and the EDOT gateway |
| `otel-demo` | `.35` | The OpenTelemetry demo |

## How it's organized

Observability is offered as **workspaces**: a workspace is a Kibana space
with its own data, access, dashboards and alerts, for one owner and one
audience. Data reaches a workspace through its data stream namespace, which
is the workspace id. Each workspace comes from the
[`terraform-elasticstack-workspace`](https://github.com/BCochofelHomelab/terraform-elasticstack-workspace)
module.

Every resource belongs to one of three scopes, and goes in the narrowest
one that contains everyone its change affects:

| Scope | Examples |
| --- | --- |
| **Shared** | Integration packages, Fleet outputs and Fleet Server, ILM, index templates, ingest pipelines, platform roles |
| **Per host group** | An agent policy and its integrations |
| **Per workspace** | A space, its data views, dashboards, rules and roles |

[Terramate](https://terramate.io) splits them into stacks, each with its
own OpenTofu state, so a change plans and applies only where it belongs.

| Path | Stack |
| --- | --- |
| `stacks/platform/elastic/`, `stacks/apps/otel-demo/` | The VMs (tag `proxmox`) |
| `stacks/shared/security`, `stacks/shared/data`, `stacks/shared/fleet` | Shared Elastic content (tag `elastic`) |
| `stacks/agent-policies/<group>/` | One host group's agent policy (tag `elastic`) |
| `stacks/workspaces/<id>/` | One workspace (tag `elastic`) |

A stack holds only its own resources. Its backend (one HCP Terraform
workspace, `platform-<path>`) and its one provider are generated by
`terramate generate` from the `*.tm.hcl` generators in [`stacks/`](stacks/), each
applied to the stacks below it, by tag, with the
shared values in [`terramate.tm.hcl`](terramate.tm.hcl): a VM stack never
gets Elastic credentials, and an Elastic stack never gets Proxmox ones.
Ansible, in [`ansible/`](ansible/), configures the VMs between the two.

## Status

Everything is in: the VMs, Ansible's roles, the shared Elastic content
(`stacks/shared/`), the host groups' agent policies (`stacks/agent-policies/`) and the
workspaces (`stacks/workspaces/`): `platform` and `otel_demo`.

## Adding a workspace or a host group

Folders hold data; Terramate generates the code (`stacks/*.tm.hcl`,
`stacks/agent-policies/agent-policy.tm.hcl`, `stacks/workspaces/workspace.tm.hcl`).

- **A workspace:** `stacks/workspaces/<id>/` with a `stack.tm.hcl` (copy one),
  a `workspace.yaml` (the module's inputs; `module_ref` pins its release
  for this workspace), optional `dashboards/*.ndjson` (Kibana exports) and
  `rules/*.yaml`, and the comment-only `main.tf` and `outputs.tf` the
  others have. The id is the folder's name: `^[a-z0-9_]{1,64}$`, never
  `default`, and it's the namespace every source of its data must write
  to.
- **A host group:** `stacks/agent-policies/<group>/` with a `stack.tm.hcl`, an
  `agent-policy.yaml` (the policy, its integrations, each with the
  workspace its data belongs to) and the same two `.tf` files; then
  `elastic_agent_policy_id: <group>` in the group_vars of the VMs that
  join it.

`terramate generate`, then `mise run lint`: the contract check fails a
namespace or a policy id that names nothing.

## Quickstart

### Set up a clone

On Linux (Ubuntu or WSL2):

```bash
mise trust && mise install   # the pinned toolchain, Ansible in .venv, git hooks
mise run check               # what CI runs: every pre-commit hook, gitleaks
```

The repository, at a glance:

| Path | What |
| --- | --- |
| `stacks/` | Every OpenTofu stack (one state each), and the Terramate generators (`*.tm.hcl`) that write their backends, providers and repeated code |
| `ansible/` | Configures the VMs: inventory from Proxmox, roles, playbooks (`site.yml`), the internal CA (`pki/`) |
| `scripts/` | The repo's own checks (the contract, telemetry, re-keying rules) |
| `docs/` | How it's set up ([`SETUP.md`](docs/SETUP.md)), OpenTofu's Elastic key, the diagram |
| `terramate.tm.hcl` | Terramate's settings and the shared values (provider pins, endpoints) |

### Make a change

1. A branch and a pull request (rules: [`CONTRIBUTING.md`](CONTRIBUTING.md)).
   After `terramate generate`, `mise run lint` must pass.
2. The **dry-run** comments on the pull request, once you approve its
   `dry-run` environment: each stack's plan line and the Ansible recap. The
   same, from your clone: `mise run ci:plan` and `mise run ci:check`.
3. Merge, then apply from your clone, on an up-to-date `main`.

### Apply (yours only)

Each task runs one command with `~/.secrets/homelab.yaml`:

```bash
mise run tofu:plan           # the stacks the last merge changed, each saved to its tfplan: review it
mise run tofu:apply          # applies exactly those plans
mise run ansible:site        # every platform VM; extra args after -- (--limit, --check --diff)
```

What `tofu:plan` plans:

- **On `main`, the stacks the previous commit changed**, which is the last
  squash-merged pull request. A stack also counts as changed when a file
  outside it that it reads does (its `watch` list in `stack.tm.hcl`: the CA,
  `elastic.sops.yaml`), or when Terramate regenerates its code.
- **Merged several pull requests since the last apply:** plan from the
  commit before them, `mise run tofu:plan -- --git-change-base=<commit>`.
- **Every stack** (a rebuild, or checking nothing drifted):
  `mise run tofu:plan -- --all`.
- **Only part of the repo:** run it from that folder; `stacks/shared`
  plans only `shared/*`.

Every plan replaces the previous one: `tofu:apply` applies the stacks that
have a `tfplan` and removes each once applied. `mise run tofu:init` runs on
every stack: once per clone, and after a provider or module version changes.

### Check it's healthy

```bash
mise run check:telemetry     # every host: its agent online in Fleet, its metrics arriving (read-only)
```

### More

- What runs where: Elasticsearch, Kibana and Logstash from Elastic's DEB
  packages; Fleet Server and the EDOT Collector gateway from Elastic's
  signed Elastic Agent tarball; the OpenTelemetry demo in Docker Compose.
  TLS inside the stack comes from an internal CA. Ansible finds the VMs in
  Proxmox by tag (`ansible/inventory/platform.proxmox.yml`), with its own
  read-only token; its secrets are in
  `ansible/inventory/group_vars/<group>.sops.yaml`, one file per group.
- Fleet Server follows `stacks/shared/fleet`, and each VM's Elastic Agent its
  host group's `stacks/agent-policies/<group>`: an `ansible:site` before
  those exist skips them with a message, the one after sets them up.
- The Elastic stacks write with one API key, scoped to what they manage:
  [`docs/ELASTIC-API-KEY.md`](docs/ELASTIC-API-KEY.md).
- Building it from nothing, or rebuilding it, with everything configured by
  hand: [`docs/SETUP.md`](docs/SETUP.md).
